# 카테고리 포함 레거시 저장소 개방 장애 수정

- 확인일: 2026-08-13
- 증상: 앱 시작 시 `캘린더 데이터를 열 수 없습니다` 차단 화면 표시
- 검증 원칙: 먼저 원본을 읽기 전용으로 확인하고 복사본에서 마이그레이션을 검증한 뒤, 별도 백업을 만든 후 설치 앱으로 실제 업그레이드

## 원인

시스템 로그의 직접 오류는 `NSCocoaErrorDomain Code=134504`, `Cannot use staged migration with an unknown model version`이었다.

사용자 저장소는 SQLite 무결성 검사를 통과했고 일정 8개와 설정 1개가 존재했다. 스키마는 과거 `51149b2` 시점의 `categoryRaw + notificationOffsetsDays: [Int]` 구조였지만, 현재 마이그레이션 계획에는 카테고리 도입 전 배열형 구조와 현재 문자열형 구조만 있었다. 이 중간 구조가 누락돼 저장소가 알려지지 않은 버전으로 판정됐다.

## 수정

- `CalendarSchemaV1_1`을 추가해 카테고리가 포함된 배열형 알림 저장소를 명시적으로 인식한다.
- 마이그레이션 경로를 `V1 -> V1_1 -> V2 -> V3`으로 구성한다.
- V1에서 V1_1은 경량 마이그레이션으로 카테고리 기본값을 추가한다.
- V1_1에서 V2는 기존 배열형 알림 값을 문자열형 필드로 복사한다.
- 기존 차단 동작은 유지해 알 수 없는 저장소를 빈 데이터나 메모리 저장소로 대체하지 않는다.

## 검증

- 수정 전 재현 테스트: 동일한 `unknown model version` 오류로 실패 확인
- 수정 후 레거시 마이그레이션 테스트 4개 통과
- 전체 테스트: 136개, 실패 0개
- release build, 앱 번들, 개인 설치 ZIP 생성 및 무결성 검사 통과
- 실제 사용자 저장소는 읽기 전용 `quick_check` 통과 및 일정 8개 확인
- 실제 저장소 가족 파일을 임시 경로로 복사하고 고유 bundle identifier 앱으로 실행
- 복사본에서 정상 달력 화면 표시, 마이그레이션 후 일정 8개·설정 1개·유효 ID 8개 보존
- 마이그레이션된 복사본의 `quick_check` 통과 및 잘못된 날짜 범위 0개 확인
- 복사본 검증 전후 원본은 구 스키마와 일정 8개를 그대로 유지
- 원본 저장소 가족 파일을 `Backups/pre-category-migration-20260813-224417`에 검증 가능한 복사본으로 보관
- 검증된 앱을 `/Applications/MyMacCalendar.app`에 설치하고 실제 저장소 업그레이드 수행
- 설치 앱에서 정상 달력 화면 표시, 실제 저장소 `quick_check` 통과
- 실제 저장소의 일정 8개·설정 1개·유효 ID 8개 보존, 잘못된 날짜 범위 0개 확인
- 업그레이드 후 최근 시스템 로그에서 `unknown model version`, 저장소 개방 실패 재발 없음

배열 속성을 읽는 동안 현재 SDK의 기존 Core Data `Array<Int>` materialization 경고는 출력되지만 마이그레이션과 데이터 비교는 통과한다.
