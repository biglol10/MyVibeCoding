# MyMarkdownViewer

긴 Markdown 문서를 편하게 읽고, 필요한 블록만 자연스럽게 수정하는 개인용 macOS 앱입니다. **첫 실행은 시스템 설정과 무관하게 다크 모드**로 시작합니다.

## 실행

배포본은 Mac·Windows 0.3.3 / Android 1.2.1입니다. 코드 블록을 클릭해도 코드 서식을 유지하고, 다이어그램 편집 시 원문과 그림을 함께 표시합니다. 앱을 다시 열면 각 기기에서 마지막 문서·읽던 위치·폴더를 복원합니다. [표시 수정과 검증 범위](docs/Code-Preview-Verification-2026-09-12.md)를 참고하세요. 사용자 승인으로 Mac 설치본을 0.3.3 (9)로 교체했습니다.

현재 배포 파일은 `dist/MyMarkdownViewer.app`과 `dist/MyMarkdownViewer-0.3.3-macOS.zip`입니다. 앱을 원하는 위치에 복사해서 실행할 수 있습니다. macOS 14 이상을 대상으로 하며 Apple Silicon과 Intel 실행 파일을 함께 포함합니다.

현재 배포본은 개인 실행용 ad-hoc 서명입니다. Developer ID 서명과 Apple 공증은 포함되지 않았습니다. 다른 Mac으로 옮겼을 때 Gatekeeper의 배포 검증을 통과하는 공증된 배포본으로 간주하면 안 됩니다.

## 사용 방법

| 동작 | 단축키 / 위치 |
|---|---|
| 새 문서 / 문서 열기 | ⌘N / ⌘O |
| 폴더 열기 | ⌘⇧O |
| 저장 / 다른 이름으로 저장 | ⌘S / ⌘⇧S |
| 실행 취소 / 다시 실행 | ⌘Z / ⌘⇧Z |
| 빠른 파일 열기 | ⌘P |
| 문서 검색 / 바꾸기 | ⌘F / ⌘⌥F |
| 폴더 전체 본문 검색 | ⌘⇧F / 사이드바 → 검색 |
| 라이브 편집 / 원문 전환 | ⌘⇧M |
| 굵게 / 기울임 / 링크 | ⌘B / ⌘I / ⌘K |
| 테마·글꼴·읽기 폭 | 앱 메뉴 → 설정, 또는 문서 옵션 → 읽기 설정 |

왼쪽 사이드바에서 파일과 목차를 전환합니다. 목차에서 제목을 검색하고, 화살표 또는 모두 접기/펼치기로 긴 목록을 정리합니다. 검색을 지우면 기존 접기 상태가 복원됩니다. 본문은 클릭한 글자 위치에서 바로 편집하며, 제목·일반 목록은 편집할 때도 간격과 들여쓰기를 유지합니다. 목록에서는 선택한 항목만 문법을 드러내고, 강조·링크·인라인 코드는 커서가 닿은 표현만 원문으로 보여 줍니다. 링크는 ⌘클릭으로 엽니다.

사이드바 오른쪽 경계를 드래그하면 너비를 조절할 수 있고 재실행 후에도 유지됩니다. 긴 파일·폴더 이름은 영역 안에서 줄임표로 표시하며, 마우스를 올리면 전체 경로를 확인할 수 있습니다. 인용문 안의 제목도 읽기 상태에서는 `####` 같은 문법 기호를 숨깁니다.

표는 **표 편집**을 눌러 셀을 수정하고 행·열 추가/삭제와 정렬을 바꿉니다. 셀은 Enter·Tab 또는 포커스를 옮길 때 반영되며 실행 취소할 수 있습니다. 여러 줄 수식·Mermaid는 클릭하면 블록 원문으로 편집합니다. 체크리스트는 체크박스를 눌러 수정할 수 있습니다. `Examples/읽기와-편집.md`에서 새 읽기 화면을 확인할 수 있습니다. 변경 내용과 복잡한 블록의 처리 범위는 [읽기 UI 개선 기록](docs/Reading-UI.md)에 정리했습니다.

테마는 다크·Night · 청회색·라이트·시스템 설정 따르기 중에서 선택하며 재실행 후에도 유지합니다. Night는 청회색 배경의 별도 테마이며 기존 다크 색상과 첫 실행 기본값은 유지합니다. 본문 기본값은 17px, 행간 1.7, 읽기 폭 800px입니다. [Night 테마와 검증 기록](docs/Night-Theme.md).

이미지는 서식 메뉴, 드래그 또는 이미지 붙여넣기로 삽입합니다. 문서 옆 `assets` 폴더에 복사하고 상대 경로로 기록합니다. 문서가 저장되지 않았다면 먼저 저장 위치를 선택합니다. 이미지 폴더 권한이 부족하면 해당 폴더를 선택합니다. 외부 이미지 자동 로드는 기본 비활성화입니다.

## 파일과 복구

- 파일은 원래 위치의 표준 Markdown으로 유지합니다. 계정·서버·자체 동기화·문서 데이터베이스를 사용하지 않습니다.
- UTF-8·UTF-8 BOM과 기존 줄바꿈을 보존합니다. 편집하지 않은 문서는 저장 시 바이트를 바꾸지 않습니다. 지원하지 않는 인코딩을 손실 변환하지 않습니다.
- 자동 저장은 입력과 조합이 끝난 뒤 1초 후 실행합니다. 새 문서는 저장 위치를 선택하기 전까지 복구본만 보관합니다.
- 다른 프로그램의 수정과 내 편집이 겹치면 자동 저장을 멈춥니다. 디스크 버전을 열거나 편집본을 다른 이름으로 저장할 수 있습니다. 외부에서 삭제된 문서를 자동 재생성하지 않습니다.
- 미저장 복구본은 파일 메뉴의 **복구할 문서 보기**에서 확인합니다. 저장 전 사본은 문서별 최근 5개를 보관합니다.
- 복구·백업은 앱 컨테이너의 `Library/Application Support/MyMarkdownViewer`에 저장합니다. 파일 접근 권한은 macOS 보안 범위 북마크로 관리합니다.
- 저장 직전 내용 비교, 파일 조정, 원자적 교체와 복구 사본을 함께 사용합니다. 파일 조정에 참여하지 않는 외부 프로그램과의 저수준 동시 쓰기를 완전히 상호 배제하는 방식은 아닙니다.
- iCloud Drive·OneDrive·Dropbox 등의 폴더를 일반 폴더로 열 수 있습니다. 공급자별 동기화 완료나 여러 기기의 동시 편집 병합을 앱이 보장하지는 않습니다.

## 개발과 빌드

Xcode 26 계열, Swift 6, Node.js 22와 npm을 사용해 검증했습니다.

```sh
npm --prefix Editor ci
./scripts/build.sh
```

빌드 전 실행 중인 앱을 종료하세요. 빌드 스크립트는 편집기와 로컬 렌더러를 번들에 넣고, 아이콘·오픈소스 고지·Xcode 프로젝트를 생성한 뒤 Universal 앱과 ZIP을 만듭니다. 이전 배포 앱은 `build/previous-release.*`에 보관합니다. 실행할 때 Node.js나 인터넷 연결은 필요하지 않습니다.

Xcode에서 직접 개발하려면 먼저 편집기 리소스를 빌드합니다.

```sh
npm --prefix Editor run build
node scripts/collect-licenses.mjs
python3 scripts/generate-project.py
```

이후 `MyMarkdownViewer.xcodeproj`의 `MyMarkdownViewer` 스킴을 사용합니다. 유효한 Developer ID 인증서가 준비되어 있다면 빌드 시 `SIGN_IDENTITY`를 지정할 수 있습니다. 공증은 별도 과정입니다.

## 구조

- `Sources/Core`: 원문·인코딩·UTF-16 변경 처리, 파일 저장·복구, 폴더 탐색, 설정.
- `Sources/App`: SwiftUI 화면, AppKit 파일 대화상자·메뉴·종료 처리, WebKit 통신, 북마크·파일 감시.
- `Editor`: TypeScript·CodeMirror 편집기, 테마, Markdown·KaTeX·Mermaid 렌더러.

통신은 문서 ID·세션 ID·리비전으로 검증합니다. Swift는 파일과 복구를, 편집기는 텍스트 변경과 실행 취소 이력을 담당합니다. Windows 앱도 같은 편집기 패키지와 메시지 계약을 사용합니다.

## 파일 관리·검색과 최신 설치본

사이드바 파일 관리, 폴더 전체 검색·바꾸기, 화면 간격·줄바꿈 보완을 포함한 Universal Release 앱과 ZIP을 2026-09-09에 다시 만들고 `/Applications/MyMarkdownViewer.app`을 교체했습니다. 기존 앱은 복구 가능하게 보관했습니다. [최신 설치 검증](docs/Release-Install-Verification.md), [사용성 검증](docs/UX-Verification.md), [파일 관리·검색 검증](docs/Workspace-Verification.md)을 참고하세요.

- 파일 탭의 `+`에서 문서·폴더를 만들고, 항목의 오른쪽 클릭 메뉴에서 이름 변경·이동·휴지통 보내기를 실행합니다. 이동 목적지는 현재 작업 폴더 안에서 선택합니다.
- 열린 문서를 이동할 때 미저장 내용을 먼저 저장합니다. 이동한 문서 내부의 상대 링크를 보정하고, 폴더 내부에서 함께 이동하는 연결은 유지합니다. 다른 문서에서 이동한 파일을 가리키는 링크는 자동 수정하지 않습니다.
- 검색 탭에서는 하위 폴더의 보이는 `.md`·`.markdown` 문서(대소문자 무관)를 일반 문자열로 검색합니다. 결과를 누르면 일치한 글자를 선택합니다. 검색할 때 작업 폴더 안의 열린 문서에 미저장 변경이 있으면 먼저 저장합니다.
- 전체 바꾸기는 변경 내용을 미리 확인하고 파일별 적용 여부를 선택합니다. 파일 변경·삭제·경로 변경을 적용 전에 재검사하며, 일부 저장만 성공하면 파일별 결과를 표시합니다. 여러 파일 변경을 한 번에 실행 취소하는 기능은 없습니다. 저장 전 백업은 기존 파일별 백업 방식으로 남습니다.
- 검색 결과가 1,000개를 넘거나 읽기 오류가 있으면 불완전한 검색임을 표시하고 전체 바꾸기를 잠급니다. 숨김 항목·심볼릭 링크·패키지 내부는 검색 대상에서 제외합니다.

표 셀 편집, 참조 링크·각주·본문 `[toc]`·문서 메타데이터 표시, 집중·타자기 모드, HTML/PDF 내보내기와 인쇄를 제공합니다. 내보내기는 전체 문서를 대상으로 하며 로컬 이미지와 수식 글꼴을 포함합니다. 외부 이미지는 내보내기에 자동 포함하지 않습니다. 이미지 파일·DOCX·EPUB 내보내기와 사용자 CSS 테마는 아직 포함되지 않습니다. 실제 두벌식 검증도 [별도 체크리스트](docs/Korean-IME-Checklist.md)의 실제 입력 결과가 필요합니다.

번들에 포함된 오픈소스 구성 요소의 라이선스는 `ThirdPartyNotices.txt`에 수록합니다.

## Windows 버전

Windows 11 Intel·AMD x64용 [포터블 ZIP](dist/windows/MyMarkdownViewer-0.3.3-Windows-x64.zip)을 전체 압축 해제하고 `MyMarkdownViewer.exe`를 실행합니다. 별도 런타임 설치는 필요 없습니다. [사용·빌드 안내](Windows/README.md)와 [검증 범위](docs/Windows-Verification.md)를 확인하세요. 실제 Windows PC 실행과 Windows 두벌식 입력은 아직 미검증입니다.

## 성능 개선 배포본

2026-09-09 성능 점검 후 Mac·Windows ZIP을 다시 생성했습니다. 큰 문서의 입력·커서 이동, 대규모 변경 저장, 유휴 파일 감시와 목록 갱신을 개선했습니다. [성능 측정과 검증](docs/Performance-Verification.md)을 참고하세요. 이번 작업은 배포 파일 생성이며 기존 Mac 설치본은 자동 교체하지 않았습니다.

### Windows 화면 재설계 (2026-09-10)

Typora Windows의 문서 중심 구성을 참고해 큰 도구 버튼을 메뉴로 정리하고,
파일/목차 사이드바·세 가지 테마·검색과 설정의 여백을 개선했습니다.
파일 이름 옆 메뉴 또는 오른쪽 클릭으로 파일을 관리하고,
하단 아이콘으로 사이드바를 접을 수 있습니다. 원문 전환은 `Ctrl+/`입니다.
[화면과 검증 기록](docs/Windows-UI-Redesign.md)을 참고하세요.
현재 Windows ZIP에는 이 재설계가 포함됩니다. Mac 설치본은 변경하지 않았습니다.

### 최종 리뷰 및 재빌드 (2026-09-12)

Windows의 메뉴·테마와 Mac/Windows `.markdown` 확장자 처리를 보완했습니다. Android는 읽기 전용을 유지합니다. [변경 및 검증 기록](docs/Final-Review-2026-09-12.md), [Android APK 1.0.1](dist/android/MarkdownReader-1.0.1-Android.apk)을 참고하세요.

### 문서 기능 확장 (0.2.0)

Mac·Windows 파일 메뉴에서 HTML/PDF 내보내기와 인쇄, 보기 메뉴에서 집중·타자기 모드를 사용합니다. 서식 메뉴에는 표·목차·각주·문서 정보·번호 목록·취소선·구분선·수식 삽입이 있습니다. Android 1.1.0은 읽기 전용으로 문서 호환성을 함께 개선했습니다. [이번 구현·검증 기록](docs/Typora-Implementation-2026-09-12.md)을 참고하세요. 배포 파일만 생성하며 기존 설치 앱은 자동 교체하지 않습니다.
