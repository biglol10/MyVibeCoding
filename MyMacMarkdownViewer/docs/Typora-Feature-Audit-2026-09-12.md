# Typora 대비 기능 재조사

조사일: 2026-09-12. 현재 작업 트리 기준이며 이전 변경 사항을 포함한다.
상태: 사용자가 권장 범위 구현을 승인하여 개발·통합 검증 중. 아래 격차 표는 구현 전 조사 기준이며, 최종 검증과 산출물은 별도 구현 기록에 정리한다.

## 조사 기준

Typora 공식 문서와 앱의 전체 명령·메뉴·렌더러·기존 테스트를 대조했다. Typora를 동일 기기에서 직접 조작한 UX 비교나 완전한 기능 동등성 인증은 아니다. 코드 존재, 메뉴 접근성, 실제 검증을 구분한다.

- [Markdown Reference](https://support.typora.io/Markdown-Reference/): 각주, YAML 메타데이터, 본문 목차와 기본 문법.
- [Table Editing](https://support.typora.io/Table-Editing/): 셀 수정, 행·열 조작과 정렬.
- [Export](https://support.typora.io/Export/): HTML/PDF/이미지 및 별도 변환 도구를 사용하는 형식.
- [Focus and Typewriter](https://support.typora.io/Focus-and-Typewriter-Mode/): 현재 블록 강조와 입력 위치 유지.
- [File Management](https://support.typora.io/File-Management/): 파일 관리, 빠른 열기, 전역 검색과 보기 방식.
- [Images](https://support.typora.io/Images/): 삽입 방식과 이미지 관리.
- [Outline](https://support.typora.io/Outline/): 제목 탐색과 본문 목차.

## 구현 시 핵심 구조

- 공통 편집기: `Editor/src/main.ts`, `livePreview.ts`, `textPreview.ts`, `markdown.ts`, `render.ts`.
- Mac 메뉴/설정 연결: `Sources/App/MyMarkdownViewerApp.swift`, `WorkspaceView.swift`, `AppModel.swift`, `Sources/Core/Settings.swift`.
- Windows 메뉴/설정 연결: `Windows/main.mjs`, `Windows/ui/index.html`, `shell.mjs`, `shell.css`.
- Android 표시: `Android/reader/reader.ts`. 현재 Lezer 최상위 블록을 직접 분리해 `renderBlock()`에 전달하여 공통 `blocksFor()`의 수식 병합을 거치지 않는다.
- markdown-it 자체는 참조 링크를 지원한다. 문제를 '참조 링크 플러그인이 없음'으로 진단하면 안 된다. 문서의 정의 정보를 블록 렌더러와 인라인 미리보기에 전달하는 구조가 필요하다.
- 출력은 편집기 DOM 캡처만으로 만들면 안 된다. CodeMirror 가상화로 화면 밖 내용이 빠지며, 활성 블록의 원문이 출력될 수 있다. 동일 원문에서 출력 전용 전체 문서를 구성해야 한다.
- 새로운 설정 필드를 추가할 때 이전 설정 저장본을 읽는 기본값 처리가 필요하다.

## 제안 개발 묶음과 완료 조건

1. 문서 호환성: 참조 링크/이미지, 각주, 메타데이터, 본문 TOC. 다른 블록의 정의 변경·중복 제목·잘못된 문법·원문 보존을 검증한다.
2. 표와 서식: 셀 수정, 키보드 이동, 행·열 조작, 정렬. 이스케이프된 파이프, 인라인 코드, 실행 취소, 조합/전환 잠금, 저장·다시 열기를 검증한다.
3. 내보내기: HTML/PDF와 인쇄부터 구현하고 이미지 출력을 별도 검증한다. 긴 문서 누락, 수식·Mermaid·로컬 이미지, 외부 이미지 동의, 페이지 잘림과 취소를 확인한다.
4. 글쓰기 환경: 집중·타자기 모드와 목차 탐색 보완. 설정 재실행 유지, 키보드 접근, 좁은 창, 한글 입력 중 화면 이동과 성능을 확인한다.

각 묶음마다 Astra가 전체 연결을 포함해 변경분을 리뷰하고 필요한 검증을 다시 실행한다. 동시 수정 파일 소유권을 분리한다. 실제 Windows PC 및 물리 두벌식 입력 검증은 로컬 Electron/WebKit 테스트로 대체하지 않는다.

## 조사 당시 검증과 확정 범위

- 현재 공통 Markdown 단위 테스트 7개 통과. 신규 기능의 검증 결과가 아니다.
- 조사 단계에서는 제품 소스나 배포 파일을 변경하지 않았으며, 이후 사용자 승인으로 구현을 시작했다.
- 사용자 승인: Mac·Windows 문서 호환성·표 편집·HTML/PDF/인쇄·집중/타자기 모드, APK 읽기 전용 표시 호환성.
- 권장 범위: Mac·Windows 핵심 읽기·편집 개선, APK는 읽기 전용을 유지하며 표시 호환성 개선.
