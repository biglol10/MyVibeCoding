# 읽기 UI 개선 기록

2026-09-06. Typora에서 참고한 읽기 흐름과 편집 전환을 기준으로 개선했다.

## 바뀐 동작

- 본문을 별도 미리보기 블록으로 교체하지 않고 실제 편집 줄에서 표시한다. 문장을 클릭하면 클릭한 단어 위치에 커서가 놓인다.
- 일반 목록과 중첩 목록은 선택한 항목만 문법을 드러낸다. 부모·주변 항목은 읽기 모양을 유지한다. 원문의 번호를 바꾸지 않으면서 읽기 화면에서는 순서대로 번호를 표시한다.
- 제목과 목록의 문법 기호에 고정된 공간을 배정해 편집 전환 시 본문 위치를 유지한다. 제목 크기·굵기, 문단 간격, 인용문, 표와 코드의 여백도 조정했다.
- 넓은 창에서 본문 최대 폭이 실제로 가운데 정렬되도록 수정했다. 기본 글자 크기 17px, 행간 1.7, 읽기 폭 800px와 첫 실행 다크 모드는 유지한다.
- 강조·기울임·취소선·인라인 코드·링크는 커서가 닿은 표현의 문법만 보여 준다. 인라인 수식은 문장 안에서 렌더링한다. 링크는 ⌘클릭으로 연다.
- 조합 중에는 미리보기 갱신과 체크박스 편집을 보류한다. 원문 전환과 실행 취소는 같은 문서 이력을 사용한다.

## 검증

Swift 9개, Markdown 유틸리티 4개, WebKit 브라우저 16개: 총 29개 자동 테스트를 통과했다.

제목에서 두 번째 목록 항목으로 이동하는 검증 문서에서 줄의 세로 위치, 본문 글자의 가로 위치, 줄 높이 변화가 모두 **0px**였다. 이 수치는 해당 예제의 전환 측정이며 모든 Markdown 문서에 대한 보장은 아니다. 읽기 폭의 중앙 정렬, 중첩 목록의 한 항목 편집, 클릭한 단어 위치의 커서, 조합 중 체크박스 잠금도 검증했다.

최종 ZIP을 별도 폴더에 설치해 실제 macOS 앱에서 읽기 화면과 목록 편집을 확인했다. 한글·이모지를 붙여 넣고 전체 원문 모드를 두 번 전환한 뒤 실행 취소했을 때, 저장된 예제 파일이 원본과 바이트 단위로 같았다. 자동 저장·저장 중 추가 입력·외부 수정·삭제·권한 실패 보호와 강제 종료 후 복구 결과는 [검증 기록](Verification.md) 및 [측정 원본](verification-results.json)에 있다.

## 현재 범위

이미지·코드·표 등을 포함한 복잡한 목록, 중첩 인용문과 목록이 결합한 블록은 기존 블록 원문 편집을 사용한다. 표 셀 전용 편집이나 모든 문법의 Typora 동작 재현까지 완료한 것은 아니다. 실제 두벌식 키보드의 조합은 별도 수동 확인이 남아 있다.

## 파일명·인용문 제목 회귀 수정과 사이드바 조절

같은 날 실제 강의 문서에서 인용문 안의 `> #### 쉽게 말하면`이 일반 인용문 줄로 처리되어 `####`가 읽기 화면에 남는 문제를 재현했다. 이제 구문 트리에서 인용문·목록 내부의 제목도 찾아 표시한다. 다른 인용문 줄을 편집해도 제목 기호는 숨기며, 해당 제목을 편집할 때만 문법을 드러낸다. 제목 뒤의 닫는 `#` 기호도 읽기 화면에서 숨긴다. 원문의 공백·기호를 자동 수정하는 방식은 아니다.

사이드바의 234pt 고정 너비를 없애고 오른쪽 경계의 드래그 조절을 추가했다. 200~560pt 범위에서 창 크기에 맞게 제한하고 선택한 너비는 앱 설정에 저장한다. 파일·폴더 행의 너비를 명시적으로 제한해 긴 이름이 줄임표로 표시되도록 했으며, 전체 경로는 도움말에 유지한다. 창 위쪽 파일명은 별도 중앙 제목 영역에서 한 줄로 줄여 표시한다.

수정 전 인용문 제목 회귀 테스트 2개가 실패하는 것을 확인했고, 수정 후 WebKit 18개·Swift 9개·Markdown 4개, 총 31개를 통과했다. 설치본에서의 드래그·너비 복원·긴 제목 검증 결과는 [사이드바·제목 검증 기록](Sidebar-Heading-Verification.md)에 정리한다.
