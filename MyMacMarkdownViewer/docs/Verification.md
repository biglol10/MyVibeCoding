# 검증 기록

검증일: 2026-09-06

## 환경

- 실행: Apple Silicon Mac, macOS 26.6.2.
- 빌드: Xcode 26.6, Swift 6.3.3, Node.js 22.23.1.
- 배포 대상: macOS 14 이상. Release 실행 파일에 `arm64`와 `x86_64` 포함.
- 서명: ad-hoc 개인 실행용. Developer ID 배포 인증서가 없어서 Apple 공증은 수행하지 않음.

## 자동 테스트

| 계층 | 결과 | 확인 내용 |
|---|---|---|
| Swift 코어 | 10개 통과 | UTF-8·BOM·혼합 줄바꿈, UTF-16 한글·이모지 위치, 외부 변경·삭제, 동시 저장, 백업, 심볼릭 링크, 복구본, 다크 기본값, Night 저장과 기존 설정 호환 |
| Markdown 유틸리티 | 4개 통과 | 코드 내부 제목 제외, 여러 줄 수식, 상대 링크 재계산, 참조형 이미지의 한글·공백·제목 보존 |
| WebKit 브라우저 | 20개 통과 | 라이트 시스템 환경의 다크 기본값, 표·수식·Mermaid, 원문 전환·실행 취소, 조합 이벤트와 체크박스 잠금, HTML·외부 이미지, Night 시작 색상·전체 렌더러·다크 복원, 제목·목록의 위치 유지, 읽기 폭 중앙 정렬, 항목별 편집, 클릭 위치의 커서, 목차 이동, 긴 문서 |

총 34개 테스트를 통과했다. 문서 전환 잠금과 한글 검색·바꾸기, 읽기 UI 전환의 회귀 검증을 포함한다. 브라우저 테스트는 처리되지 않은 JavaScript 오류도 실패로 취급한다. 제목에서 목록 항목으로 이동하는 예제의 세로 위치·글자 가로 위치·줄 높이 변화는 모두 0px였다.

긴 문서 측정은 2,990,014바이트·20,003줄의 한글·영문 문서로 수행했다. Production 웹 번들을 WebKit에서 열어 첫 두 프레임까지 **234ms**, 20회 입력 중 p95 처리 시간 **34ms**를 기록했다. 이는 편집기 측정이며 파일 대화상자·디스크 I/O를 포함한 전체 앱 시작 시간은 아니다.

현재 Mac의 Release 설치본에서는 같은 2,990,014바이트·20,003줄 문서를 디스크에서 읽어 화면의 두 프레임까지 **1,141ms**, 프로그램 편집 명령 처리 p95 **76ms**로 측정했다. 대화상자와 앱 프로세스 시작 시간은 제외한다. 물리 키 입력·IME의 전체 지연 측정은 아니다.

## 실제 앱 확인

ZIP을 별도 설치 검증 폴더에 풀고 해당 앱을 실행했다. 개발 서버 없이 앱 내부의 HTML·JavaScript·CSS·글꼴 리소스를 사용했다.

- 다크·Night·라이트 전환과 문서 배경색을 실제 WKWebView에서 확인. 설정에서 고른 Night가 완전 종료·재실행 후에도 유지되며, 최초 문서 검사에서 청회색 배경으로 나타나는 것을 확인.
- 자동 저장, UTF-8 BOM·CRLF 유지, 저장 후 실행 취소, 수정하지 않은 파일의 바이트 동일성을 확인.
- 이전 세션의 변경 메시지 무시, 외부 변경 시 깨끗한 문서의 새로고침, 미저장 변경이 겹칠 때 저장 중단을 확인.
- 복구본의 저장과 다시 열기를 확인.
- 이전 읽기 UI 배포본에서 복구본을 디스크에 기록한 후 검증 앱 프로세스를 SIGKILL로 종료하고, 새 프로세스에서 미저장 편집본과 외부 변경 충돌 상태를 복원하는 것까지 확인.
- 네이티브 폴더 선택·파일 트리·문서 전환, 목차, Mermaid, 코드 강조, 한글·공백을 포함하는 상대 이미지 경로를 화면에서 확인.
- 읽기 UI 개선 후 별도 설치본에서 제목·일반 목록·중첩 목록·인라인 수식의 표시와 한 항목 편집을 확인. 한글·이모지 붙여넣기 → 원문 모드 왕복 → 실행 취소 후 저장 파일의 바이트 동일성을 확인. 상세 내용은 [읽기 UI 개선 기록](Reading-UI.md)에 있다.

원본 요구사항 문서는 수정하지 않고 검증용 복사본을 사용했다.

2026-09-06 추가 검증에서 실제 파일 쓰기를 지연시킨 상태의 추가 입력, 외부 삭제, 폴더 쓰기 권한 제거, 미지원 인코딩 열기를 확인했다. ⌘W 누락, 문서 전환 잠금 중 서식·체크박스 수정, 변경 버리기 후 복구본 재생성 문제를 수정하고 재검증했다. 상세 내용은 [실기기 검증 기록](Acceptance-2026-09-06.md)에 있다.

2026-09-06 사이드바·인용문 제목 수정 후 최종 ZIP에서 저장·복구 검증을 다시 통과했다. 실제 경계 드래그(200~560pt), 재실행과 숨김/표시 후 388pt 복원, 긴 파일명 줄임, 인용문 제목의 문법 숨김을 확인했다. 강제 종료 후 재실행 검증은 이전 배포본 결과로 구분해 기록했다. [이번 수정의 상세 검증](Sidebar-Heading-Verification.md).

2026-09-06 Night 테마 추가 후 새 ZIP 설치본에서 테마·저장·복구 검증을 다시 통과했다. 이전 다크 색상과 기본값을 유지하고, Night 선택·재실행 유지·본문과 사이드바 색상을 실제 앱에서 확인했다. [Night 테마 상세 기록](Night-Theme.md). 이전 배포본의 검증 결과는 `verification-before-night.json`에 보관한다.

## 남은 확인 범위

- **실제 두벌식 키보드 조합:** 자동화 도구가 macOS 기본 텍스트 필드에서도 `g`, `k`, `s` 입력을 `ㅎㅏㄴ`으로 분리했다. 이 방식은 실제 키보드 조합 검증으로 인정하지 않았다. 조합 이벤트 보류, 한글 텍스트 보존·저장과 실행 취소는 별도로 검증했다.
- Intel Mac 및 macOS 14의 실제 실행: Universal 컴파일 확인까지 수행했다.
- iCloud Drive·OneDrive·Dropbox의 실제 계정별 내려받기·동시 수정: 공급자별 실사용 검증은 수행하지 않았다.
- 공증된 앱의 다른 Mac 배포: Developer ID·공증 전에는 확인 완료로 표시하지 않는다.

## 재현

일반 테스트는 README의 명령을 사용한다. 설치본 검증 모드 `--qa`는 앱 컨테이너의 `Library/Application Support/MyMarkdownViewer/QA` 아래에서만 실행된다. `--qa-root`로 해당 경로를 지정하고 `--open`에는 그 아래의 검증 문서를 지정한다.

검증 모드는 해당 폴더에 테스트 문서·복구본·스크린샷·JSON 보고서를 만든다. `--qa-crash`는 복구본 기록 후 **검증 앱 자신을 강제 종료**하며, `--qa-recover`는 다음 실행에서 그 복구본을 확인한다. 실제 작업 문서에서 실행하지 않는다.

Xcode 로그의 App Intents 메타데이터 추출 생략 메시지는 이 앱이 App Intents를 사용하지 않아 발생한다. Swift 컴파일 오류·경고와 편집기 런타임 오류는 별도로 확인한다.
