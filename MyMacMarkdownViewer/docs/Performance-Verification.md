# Mac·Windows 성능 점검 — 2026-09-09

성능 병목을 수정하고 Mac Universal ZIP과 Windows x64 포터블 ZIP을 다시 생성했습니다. `/Applications`의 기존 Mac 설치본은 교체하지 않았습니다. 최신 파일과 해시는 `performance-verification-results.json`에 기록합니다.

## 측정한 개선

동일한 macOS 26.6.2 Apple Silicon 호스트에서 생성한 문서·폴더로 비교했습니다. 반복 측정 중 p95는 느린 쪽 5%에 해당하는 값이며 물리 키보드 응답 시간과 구분합니다. 작은 시간 차이는 호스트 부하의 영향을 받습니다.

| 사례 | 수정 전 | 수정 후 |
|---|---:|---:|
| 약 2.08MB·10,003줄 문서 커서 이동 p95, WebKit | 22ms | 4ms |
| 같은 문서 프로그램 입력 p95, WebKit | 24ms | 13ms |
| 같은 문서 열기에서 두 프레임까지 | 691ms | 264ms |
| Mac 4,000줄 전체 변경의 CRLF 저장 인코딩, 최적화 컴파일 | 46,806ms | 16ms |
| Windows 코드·1,200개 파일·5.2초 유휴 중 문서 전체 읽기 | 3회 | 0회 |
| 같은 유휴 구간의 전체 폴더 탐색 | 1회 | 0회 |
| 20회 입력·자동 저장까지 파일 목록 DOM 변경 | 27,623건 | 0건 |
| 같은 구간의 파일 목록 배열 IPC 전송 | 23회 | 0회 |

Windows 수치는 실제 Windows 장비가 아닌 **macOS에서 동일한 Electron 앱 코드를 실행한 결과**입니다. 이전 Windows 배포본의 `app.asar`와 수정 코드를 같은 조건에서 비교했습니다. 개선 후에도 저장 전 원본 해시 확인·백업·충돌 감지에 필요한 읽기는 유지합니다.

## 주요 수정

- `Editor/src/livePreview.ts`: 커서 이동과 편집 시 영향을 받은 블록만 다시 장식합니다. 바뀌지 않은 표시 장식은 위치를 매핑해 재사용합니다. 읽기 전용 잠금 등 표시와 무관한 명령에는 전체 갱신을 생략합니다. 조합 중에는 기존 표시를 유지하고 조합 종료 시 다시 계산합니다.
- `Editor/src/main.ts`, `markdown.ts`: 목차에 이미 파싱한 트리를 재사용하고, 글자·단어 수를 셀 때 큰 임시 배열을 만들지 않습니다.
- `Sources/Core/DocumentCodec.swift`: LF 및 일정한 줄바꿈은 줄 비교를 생략합니다. 혼합 줄바꿈은 공통 앞뒤 구간을 먼저 보존하고, 대규모 재작성은 비용이 제한된 줄 대응 방식을 사용합니다. 원문·BOM·남아 있는 줄의 줄바꿈을 검증했습니다.
- `Sources/App/AppModel.swift`: 값이 같을 때 불필요한 화면 상태 알림을 보내지 않습니다. 파일 변경 알림을 모아서 확인하고 저장 중 발생한 확인을 지연 처리합니다.
- `Windows/main.mjs`, `core.mjs`, `ui/shell.mjs`: 파일 변경 알림 중심의 감시, 15초 메타데이터·60초 폴더 안전망, 중복 복구 기록 방지, 변경된 트리만 전송·갱신합니다. 비동기 기록 revision과 파일 내용·서명 대응을 리뷰했습니다.
- 두 플랫폼 폴더 검색: 파일당 32MiB, 보관 데이터 예산 64MiB를 적용합니다. 초과한 결과는 불완전함을 표시하여 검토 후 바꾸기를 막습니다. 이 예산은 프로세스 전체 메모리 한도를 의미하지 않습니다. Mac의 결과 수 반복 합산도 제거했습니다.
- `Windows/scripts/prepare-editor.mjs`: 오래된 생성 리소스를 이전 빌드 폴더로 옮긴 뒤 최신 편집기만 포장합니다.

## 검증

- Swift Core 29개, Windows Core 13개, Markdown 7개, WebKit 27개 통과.
- 새 검증: 4,000줄 전체 변경, 8,000줄 혼합 줄바꿈, 검색 용량 한도, 정확한 결과 수 경계, 부분 표시 갱신과 전체 갱신의 동등성·실행 취소.
- Electron 저장·이름 변경·검색·선택 바꾸기·다른 이름 저장·외부 변경·복구 등 17항목과 실제 UI 9항목 통과. 1,200개 파일 성능 검증은 실제 파일 저장 결과와 유휴 I/O·DOM·메시지 횟수를 함께 확인합니다.
- 최종 Windows ZIP의 전체 편집기·UI·주요 코드 일치, PE AMD64, 런타임·라이선스 포함, 압축 무결성을 검사했습니다. ZIP 안의 `app.asar`도 Mac Electron에서 직접 실행해 연결 검증했습니다.
- Mac 앱은 Universal arm64/x86_64, 코드 서명 검증, ZIP의 241개 파일 일치와 현재 편집기 리소스 일치를 검사했습니다. 별도 식별자의 최종 Release QA 사본으로 네이티브 검증을 실행합니다. 최종 2.99MB·20,003줄 문서 열기 약 667ms, 편집기 프로그램 입력 p95 19ms, Swift 모델의 수신 완료까지 p95 약 43ms였으며 저장·복구·충돌·이동·검색 네이티브 검증이 모두 통과했습니다. 구체적인 결과는 JSON에 기록합니다.

재현 도구: `Editor/scripts/performance.mjs`, `Windows/tests/electron-performance.mjs`, `Windows/tests/electron-smoke.mjs`, `Sources/App/AppQA.swift`. 네이티브 QA는 프로그램 편집 이후 Swift 모델의 revision 수신 완료까지 별도로 측정합니다.

## 제한

실제 Windows PC 성능·Windows IME, 실제 Intel Mac 실행, macOS 14 실행, 물리 두벌식 입력, 실제 클라우드 동기화 폴더는 미검증입니다. Mac은 개인용 ad-hoc 서명이며 공증하지 않았고 Windows는 서명 없는 개인 배포본입니다. 대형 문서에서 모든 작업이 일정한 지연 이하라고 보장하지 않습니다. 집중·내보내기 등 미구현 기능을 이번 성능 수정에 추가하지 않았습니다.

`.codex/lessons.md`에 무제한 비교 비용, 검색 보관량, 비동기 기록의 revision, 측정 범위·검증 오류의 예방 규칙을 기록했습니다.
