# 추가 개선 조사와 빠른 파일 열기 보완

2026-09-12. 기존 작업 트리의 변경을 보존했다. Astra가 Mac 구현·전체 변경 리뷰·직접 재검증을 맡고 Terra는 Windows, Luna는 Android 탐색 및 Mac 감시 지연을 조사했다.

## 이번에 수정한 동작

- Windows 빠른 열기에서 Enter로 선택 파일을 연다. 위·아래 화살표로 선택하며 긴 목록에서도 선택 항목이 보인다. 닫기와 Escape는 현재 문서를 유지한다.
- Windows 검색 결과는 파일명과 상대 경로를 구분해 보여 준다. 목록 갱신으로 선택 파일이 사라지면 선택을 재설정한다. 검색 입력의 접근성 정보와 조합 중 Enter/화살표 보호를 추가했다.
- Mac 빠른 열기에 결과 없음 안내, 열기 비활성화, 긴 경로 줄임 표시와 갱신된 목록에 맞는 선택 상태를 추가했다. 열 때 목록을 다시 조회하고 직접 새로고침할 수 있다.
- README의 현재 배포 파일 링크와 지원 확장자 안내를 실제 0.2.2 / Android 1.1.2 기록에 맞췄다. 이번 변경을 포함한 새 배포본은 아직 만들지 않았다.

주요 파일: `Sources/App/WorkspaceView.swift`, `Windows/ui/shell.mjs`, `Windows/ui/shell.css`, `Windows/tests/electron-navigation.mjs`, `README.md`, `Android/README.md`.

## 우선순위가 높은 추가 후보

| 순서 | 후보 | 필요한 이유와 범위 |
|---|---|---|
| 1 | Mac·Windows·Android 목차 검색과 하위 제목 접기 | 긴 문서의 제목을 빨리 찾는다. 중복 제목, 제목 레벨 건너뜀, 문서 변경 후 상태 초기화와 정확한 이동을 검증해야 한다. |
| 2 | Android 현재 폴더 파일명 검색 | 최대 1,000항목의 목록을 좁힌다. 현재 폴더 안의 파일·폴더 이름을 대상으로 명시하고, 하위 폴더 전역 검색과 구분한다. |
| 3 | Android 목차의 현재 읽는 위치 표시 | 스크롤 후 현재 절을 파악하기 쉽게 한다. 긴 문서에서 매번 전체 목록을 다시 만들지 않는 방식이 필요하다. |
| 4 | 최근 문서 바로 열기 | 반복해서 읽는 파일에 빠르게 접근한다. 삭제·이동·만료된 접근 권한·미저장 문서 전환을 처리해야 하므로 별도 범위로 진행한다. |

현재 Mac·Windows 빠른 파일 열기와 본문/폴더 검색, Android 목차·본문 검색·폴더 열기는 이미 존재한다. 이 기능들을 누락으로 판단해 다시 구현하지 않는다. Android는 읽기 전용을 유지한다.

후속 작업에서 권장한 1차 범위(1~3번)를 진행했다. 최근 문서 바로 열기(4번)는 별도 후속 후보로 남긴다. 현재 구현·배포 검증은 [목차 탐색 개선 기록](Outline-Navigation-Release-2026-09-12.md)을 참고한다. 아래 검증은 후보 조사 당시의 기록이다.

## 검증과 남은 제한

- Windows 기존 코드에서 Enter 후 문서가 열리지 않는 실패를 재현했다. 수정 초안의 닫기 버튼이 제출 버튼으로 처리되는 문제도 Astra 리뷰에서 발견하여 수정했다.
- Astra가 최종 navigation 테스트와 관련 UI·컨텍스트 메뉴 검증을 직접 실행하여 통과했다. 30개 결과 스크롤, 한글 경로, 목록 갱신, 빈 결과, 조합 이벤트와 취소 후 원문 유지를 검사했다.
- Windows 800×560 화면을 캡처하고 직접 검토했다. 테스트 환경은 macOS arm64의 Electron 44.3이며 실제 Windows 기기가 아니다. 합성 조합 이벤트는 물리 한글 키보드 검증을 대신하지 않는다.
- Mac Swift 빌드와 최종 arm64 Release 빌드를 통과했다. 실제 별도 QA 앱에서 한글 검색·Enter 열기, 빈 결과, 새로고침에 따른 선택 해제, 다시 열 때 최신 목록 조회 및 취소를 확인했다. 사용자 파일은 수정하지 않았고 검증 파일의 원문도 보존했다. QA 앱은 종료했다.
- Mac QA 앱의 폴더 감시 초기화가 `FSEventStreamCreate`에서 지연되는 현상을 관측했다. 단일·동시 감시 harness는 통과해 원인은 아직 확정하지 못했다. 이번 수정은 빠른 열기의 직접 재조회 경로를 제공하며, 감시 엔진 자체가 해결됐다는 뜻은 아니다.
- Android는 코드 조사만 수행했다. APK 재검증이나 새 기능 구현으로 기록하지 않는다. 기존 Mac 설치본과 배포 파일은 유지했다.

상세 실행 기록: [검증 결과](navigation-validation.json).
